# Kitchen CAD

Браузерный параметрический конструктор кухни с приоритетом мобильного интерфейса. Одна модель данных используется для визуализации, размеров, предварительной деталировки и экспорта.

**Live:** https://kitchen-cad.pages.dev/

**Резервный адрес (GitHub Pages):** https://den-2020.github.io/kitchen-cad/

> Текущий статус: развивающийся прототип, а не сертифицированная CAD/CAM-система. Перед производством размеры, вырезы, кромку, крепёж и зазоры необходимо проверить с конкретным цехом и инструкциями техники/фурнитуры.

## Реализовано

- полноэкранный mobile-first интерфейс и desktop-режим;
- RU / EN и светлая / тёмная тема;
- редактируемые размеры комнаты;
- выбор модуля и отдельных объектов прямо на сцене;
- перемещение выбранного модуля по комнате;
- вращение 3D-сцены по двум осям, масштаб, виды спереди и сверху;
- нижние, навесные шкафы, шкаф под **раковину**, стиральная и посудомоечная машины, духовка, холодильник;
- размеры Ш × В × Г, положение X/Z, материал корпуса/фасада;
- 1–4 створки или авто-режим;
- свес фасада сверху/снизу/слева/справа — фасад может быть больше корпуса;
- плоские, рамочные, стеклянные и реечные фасады (пока визуальная модель);
- варианты ручек и ножек;
- автоматическая сегментная столешница: несколько прогонов и стыков, глубина, толщина, высота, свес и декор;
- раковина и варочная поверхность как встраиваемые элементы, привязанные к выбранному нижнему шкафу;
- предупреждения и красная подсветка при выходе за комнату, пересечении модулей, неверном перекрытии столешницей или слишком большом встраиваемом элементе;
- размеры: основные / выбранного элемента / все детали;
- разобранный вид с ползунком расстояния разнесения;
- предварительная деталировка и CSV;
- автосохранение со статусом, история до 80 шагов и undo/redo;
- безопасный импорт и экспорт проекта JSON;
- экспорт PNG и многостраничного PDF с обзором и листами деталей;
- автоматические тесты расчётного ядра и деплой через Cloudflare Pages / GitHub Pages.

## Важные ограничения

- Раковина и варочная поверхность сейчас создают параметрический габарит/контур выреза. Для производства нужен точный шаблон конкретной модели производителя.
- Стили рамочных/стеклянных/реечных фасадов пока меняют визуализацию; технологическая фрезеровка, стекло и профиль ещё не входят в спецификацию.
- Техника пока параметрическая. Следующий визуальный слой — оптимизированные GLB/GLTF-модели с сохранением наших точных габаритов.
- PDF содержит обзор и отдельные листы модулей, но ещё не заменяет цеховой раскрой и технологические карты.
- Пока нет схем сверления Blum/Hettich, автоматической оптимизации листового раскроя, DXF и инженерного расчёта каменной столешницы.

## Архитектурный принцип

```text
Project JSON
   ↓
validate / layout
   ↓
buildProject
   ├── scene objects
   ├── Parts[]
   ├── fixtures
   ├── issues / warnings
   └── countertop
          ↓
       UI / CSV / PNG / PDF
```

Расчётные формулы находятся в `src/core`, а не в UI. Поэтому смена темы, 3D-модели техники или интерфейса не должна менять производственные размеры.

## Разработка на Windows 11

Нужен Node.js 22.16+.

```powershell
npm ci
npm test
npm run build
```

GitHub Pages публикуется workflow-файлом `.github/workflows/pages.yml` после push в `main`.
Cloudflare Pages также автоматически публикует `main`; автоматические preview-сборки
для остальных веток отключены, чтобы не расходовать лимит сборок без необходимости.

## Локальная база и синхронизация

Редактор по-прежнему сначала сохраняет проект в браузере. Дополнительно он может
синхронизировать проект с SQLite на домашнем ПК через защищённый HTTP API. Если ПК
выключен или туннель временно недоступен, редактирование и локальное автосохранение
продолжают работать.

Первичная настройка на Windows:

```powershell
npm run sync:init
npm run sync:server
```

`sync:init` создаёт случайный секретный ключ в `.env.local`. Файл исключён из Git.
По умолчанию база находится в `%LOCALAPPDATA%\KitchenCAD\data.db`, ежедневные копии —
в `%LOCALAPPDATA%\KitchenCAD\backups`, а последние 50 ревизий каждого проекта
хранятся внутри SQLite.

Для автоматического запуска после входа в Windows:

```powershell
npm run sync:install
```

Удалить задачу автозапуска можно командой `npm run sync:uninstall`. Лог сервера
записывается в `%LOCALAPPDATA%\KitchenCAD\server.log`.

Локальный API слушает только `127.0.0.1:8787`. Для телефона нужно создать отдельный
Cloudflare Tunnel с публичным HTTPS-именем и направить его на
`http://127.0.0.1:8787`. Рекомендуется remotely-managed tunnel из Cloudflare
Dashboard. Пример локальной конфигурации находится в
`cloudflared/config.example.yml`. Сам файл SQLite и порт SQLite наружу не публикуются.

После создания туннеля в панели «Проект → Локальная база на компьютере» указываются:

- HTTPS-адрес туннеля;
- код проекта, например `main`;
- секретный ключ из `.env.local`.

Первую синхронизацию нужно выполнить вручную кнопкой «Сохранить на ПК» или
«Загрузить с ПК». После этого можно включить автосинхронизацию. API использует
optimistic locking: при параллельных изменениях на двух устройствах новая версия
не перезапишет старую молча, а покажет конфликт.

## Cloudflare Pages

Покупать домен не обязательно: Cloudflare выдаёт проекту адрес вида
`https://<project>.pages.dev`. Для Git-интеграции используйте:

- production branch: `main`;
- build command: `npm run build`;
- output directory: `dist`;
- environment variable: `NODE_VERSION=22.16.0`.

Сборка использует относительные пути к ресурсам, поэтому один и тот же `dist`
работает на GitHub Pages, Cloudflare Pages и preview-адресах. Cloudflare Tunnel
лучше оставить для временного показа локального dev-сервера, а не для постоянного
размещения приложения.

## 3D assets

Для будущих реалистичных моделей предпочтительны ассеты с понятной лицензией (в первую очередь CC0), например Quaternius / Kenney / Poly Haven. Перед включением модели должны быть оптимизированы по полигонам, текстурам и размеру загрузки для мобильных устройств.
