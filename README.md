# Kitchen CAD

Рабочий прототип браузерного параметрического конструктора кухни. Цель проекта — связать одну модель данных с 3D-представлением, изменяемыми размерами, материалами и предварительной деталировкой для распила.

> Статус: MVP 0.1.0. Это ещё не сертифицированная производственная CAD/CAM-система — перед заказом деталей расчёты требуют проверки под конкретный цех, фурнитуру и технику.

## Что уже реализовано

- нижний шкаф, шкаф под мойку, навесной шкаф и габаритный макет стиральной машины;
- изменение ширины, высоты, глубины, толщины плит, ножек и зазоров;
- 3D-вид, виды спереди/сверху/сбоку, вращение и масштабирование;
- скрытие фасадов и столешницы, разнесённый вид деталей;
- материал-основа отдельно от декора/цвета/глянца/направления рисунка;
- ЛДСП, МДФ, фанера, камень для столешницы; однотонные декоры, дуб, орех, камень и бетон;
- список деталей с готовыми размерами и размерами заготовок с учётом кромки;
- экспорт CSV и схемы детали SVG;
- импорт/экспорт проекта JSON, локальное сохранение, Undo/Redo;
- 32 автоматических теста расчётного ядра.

Начальная сцена `600 + 500 + 600 мм` — только демонстрация и не является реальным обмером кухни.

## Архитектурный принцип

```text
Project JSON
   ↓
validate / layout
   ↓
buildProject
   ├── 3D objects
   ├── Parts[]
   ├── warnings
   └── countertop
          ↓
      CSV / SVG / UI
```

Формулы размеров находятся в `src/core`, а не в UI или рендерере. 3D и деталировка используют один и тот же результат расчёта, поэтому изменение размера модуля не должно приводить к расхождению картинки и списка деталей.

Материал-основа (`ЛДСП/МДФ/...`), декор, цвет, глянец и направление рисунка хранятся раздельно. Это позволит позже подключить реальные каталоги Egger/Kronospan и PBR-текстуры без переписывания геометрического ядра.

## Структура

```text
src/
├─ catalog/       материалы и декоры
├─ core/          модель проекта и расчёт деталей
├─ io/            JSON / CSV / SVG
├─ render/        3D и CPU fallback
└─ ui/            интерфейс

docs/             архитектура и статус
scripts/           сборка и локальный сервер
tests/             тесты расчётов
.github/workflows/ CI и GitHub Pages
```

## Запуск на Windows 11 / PowerShell

Нужен Node.js 22.16+.

```powershell
npm test
npm run build
npm start
```

После `npm start` открыть `http://127.0.0.1:4173`.

## GitHub Pages

Workflow `.github/workflows/pages.yml` собирает автономный `dist/index.html` и публикует его через GitHub Pages.

Один раз нужно выбрать в GitHub:

**Settings → Pages → Source → GitHub Actions**.

Планируемый адрес:

`https://den-2020.github.io/kitchen-cad/`

Сейчас репозиторий создан как **Private**. Для GitHub Pages из private-репозитория нужен подходящий платный план GitHub; на бесплатном варианте проще переключить репозиторий в **Public**. Само приложение от этого менять не нужно.

## Ограничения MVP

Пока нет подтверждённых схем сверления под Blum/Hettich, реальных моделей техники GLB, вырезов мойки/варочной, расчёта опор каменной столешницы, раскроя листов с оптимизацией остатков, DXF/PDF производственного комплекта и угловой/П-образной кухни.

Размеры заготовок сейчас рассчитываются по соглашению «готовый размер после кромления». Перед реальным распилом необходимо согласовать с конкретным цехом, принимает ли он готовые размеры или сам вычитает толщину кромки.

Подробности: `docs/ARCHITECTURE.md`, `docs/STATUS.md`, `AGENTS.md`.
